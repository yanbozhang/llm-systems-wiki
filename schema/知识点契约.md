# 知识点契约

版本：1.0。一个主题由多个可独立学习的知识点组成；每个知识点都要把问题、公式、教学代码、实现结构和来源连在一起，不能只给整篇文章添加一个通用示意图。

## 权威清单

knowledge/topics.json 记录主题；knowledge/units.json 记录知识点。每个知识点包含唯一非空 id、topic、title、example、function、source_ids、claim_id。title 对应主题页中“知识点”开头的三级标题，example 指向 examples 下的 Python 文件，function 指向该文件内的顶层函数，claim_id 指向本知识点的核心声明。

每个主题至少包含三个已登记知识点。登记标题与页面标题一一对应，不允许同主题重复标题或正文出现未登记的知识点。id 可以稳定保留，标题修订时同时修改清单和正文。

## 每点必备内容

每点至少包含一个非空双美元公式块、一个非空 python 代码块、一个非空 mermaid 结构图块，正文应解释符号、代码步骤、图中组件关系及适用条件。Python 代码块应能被AST解析，并定义或调用登记的函数，使正文与完整教学实现相互关联；只有注释或语法错误的占位内容不能满足要求。

公式既可以来自论文，也可以是清楚标注的状态、预算或评价模型；不能把自主抽象冒充作者原始定义。代码可以是教学简化，但必须说明与生产实现的差异。闭源产品只根据公开文档和可公开读取的SDK/扩展说明边界，不伪造内部源码。

公式必须同时兼容GitHub文件预览与阅读网站。自定义函数、统计量及算子名称统一使用直立字体写法，例如 `\mathrm{Var}(X)`、`\mathrm{softmax}(S)`；常用函数沿用 `\log`、`\exp`、`\min`、`\max`。不依赖额外宏包或自定义命令。排版兼容性修订应保留符号、上下标、参数与数学含义，并分别检查两处实际展示。

source_ids 为非空的已登记来源ID列表。每点的 claim_id 必须属于相同主题，并包含该知识点列出的来源。每个主题的知识点合计至少连接两个不同URL，避免将同一来源重复登记后伪装成多源材料；来源是否真正支持结论仍需语义核对。

## 检查器行为

scripts/learning_check.py 的 check(root) 返回错误列表，不发起网络请求、不执行教学代码、不修改文件。CLI支持 --root；结构通过退出0，有错误退出1，并输出可定位的中文错误。

检查 JSON 数组、元素和字段类型、ID唯一性、主题和声明引用、来源引用、标题登记、每主题最少知识点数及每点公式/代码/图。主题路径必须解析到 wiki 内，示例路径必须解析到 examples 内，且为存在的 .py 文件；不读取越界路径。示例中的函数必须能通过AST解析定位。

支持本库采用的ATX标题、反引号或波浪线围栏、双美元公式块。代码和HTML注释里的假标题不能成为知识点，代码或注释里的假公式与假图不能满足要求；围栏/公式未闭合应报告错误。它不是完整CommonMark解析器，也不验证数学结论或源码语义。

## 实际验证与发布

教学示例由单元测试验证小输入数学值、状态不变量、已声明边界及可执行入口。公式与图分别进行语法和实际渲染检查；需要执行真实模型、框架或设备的实验单独记录，不能由教学测试自动升级为“已复现”。

新增或修订一个知识点时同步主题、知识点、声明、来源和相关路径；在本次提交的CI通过后再发布版本。历史发布清单保持原样，以对应Git标签还原。
