# 维护工具契约

本契约描述基础维护行为，v0.2扩展以学习体系契约为准。基础行为将结构检查、来源去重、读取状态和模块轮换要求约束为首版可执行行为。它先于实现确定验收边界。

## 内容检查

`check(root)` 返回错误列表，空列表表示结构通过。校验 JSON 对象集合中的稳定 ID 唯一且非空；topic 的模块合法、页面存在；每个 topic 恰好对应一个页面，page 路径不得逃出仓库；claims 的 topic、source_id 与 source_version 必须存在且匹配；source_version 是本次快照身份，不自动等于原文版本号。来源处于 withdrawn 时不可作为有效声明依据。正式 prerequisite 关系采用 from 先修于 to 的方向，不允许自环、未知端点或有向环；其他关系允许成环。知识页面内相对 Markdown 文件链接必须存在，不允许逃出仓库。HTTP 链接在线可用性不由离线检查证明。所有文档使用普通行内链接，图片和代码块不纳入本次离线链接检查。

## 巡检与候选

`parse_feed(xml, feed_id)` 支持 Atom 和 RSS 2.0；提取每项稳定 ID（优先 id/guid，其次链接）、标题、HTTP(S) 链接和来源给出的更新时间，缺失日期记空值。没有稳定 ID 或链接的项不进入候选。候选键按 feed_id、条目标识、更新时间、标题与链接的规范 JSON 内容 SHA-256 生成，同一条目同内容重复导入不产生新键，有实质字段修订产生新版本。订阅源格式无效或不是受支持的根元素时失败，不能冒充空订阅。

`discover(feeds, state, fetcher, now)` 顺序处理配置列表。state 包含 `seen`（已持久化候选的键）与 `checked`（每个订阅最后成功时间）；输入 state 不被修改。抓取成功且解析成功才更新 checked；单源失败记录 error，其余源继续；结果有 changed、unchanged、partial_failure、failed 四种状态。只要有一源失败，本次不可报告 unchanged。先得到完整返回结果，由 CLI 写候选文件，再原子写 state；失败文件写入不得推进检查点。回传候选只表示发现线索，不等于已经读取全文或知识改变。限额读取造成的漏项风险显式保留，本版无历史补采保障。

抓取仅接收 https:// 下已登记订阅；禁止带用户信息、localhost 和 IP 字面量，最多读取 2 MiB、超时 20 秒。不下载论文附件，不运行来源脚本。网络调用不附带任何用户凭证。输入源由仓库维护者控制，DNS 重绑定防护与全历史分页是后续范围。

## 学习轮换与命令

`plan(day, root=None)`从模块与主题清单生成七模块计划，周日为Benchmark并标记review_due；不再写死每模块四个主题。日期格式和上海时区保持不变。能力、课程与知识单元检查详见[学习体系契约](学习体系契约.md)。

CLI 提供 check、plan、discover。check 结构失败退出 1；discover 全部或部分源失败退出 1，但仍保存候选和失败结果供检查。输入文件损坏、读取或写入失败均退出非零，不能覆盖旧状态。产物目录由 --output 指定，默认为 candidates；check 和 plan 不修改知识页面或个人笔记。
