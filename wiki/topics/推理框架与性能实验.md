# 推理框架与性能实验

vLLM 和 SGLang 都是可用于学习服务系统的入口。首版从论文机制与官方设计理解框架，暂不提供未经本机验证的安装配方或通用性能排行。

前置学习：[缓存分页与连续批处理](缓存分页与连续批处理.md)。所属模块：[推理](../modules/推理.md)。

## 基本机制

实验先固定模型及 revision、tokenizer、dtype、硬件、驱动、框架 commit 或 release，再定义到达过程、长度分布和并发。至少分冷启动、稳态、前缀复用三类场景；记录 TTFT、逐 token 延迟、输出吞吐、错误率和显存峰值。压测生成器是否成为瓶颈也要检查。

依据：[PagedAttention 原论文](https://arxiv.org/html/2309.06180v1)；[SGLang 原论文](https://arxiv.org/html/2312.07104v2)。完整来源与章节定位见[来源索引](../../sources/来源索引.md)。

## 方法演进

vLLM 原论文聚焦分页缓存与高吞吐服务；SGLang 原论文将结构化程序执行、缓存复用和受约束生成结合。当前产品能力应核对具体版本发布说明，不能靠早期论文推断所有新功能。

## 适用条件与限制

本文是实验设计，不包含实测性能数值。与不同硬件、量化或任务设置的排行榜不直接横比；单请求实验不能代表高并发容量。

## 常见误区

仅换服务引擎却同时改变 chat template、量化和生成长度，会使速度与质量差异无法归因。仅检查 HTTP 成功也无法验证生成质量。
