# GitHub 仓库绘图标准指南

仓库适配版 1.0，2026-11-26。依据本次任务提供的绘图规范与 Harness 分区示例，结合现有 Markdown、知识清单和 Astro 资源映射整理。此文件是本仓库的实施约定，不是第三方内部文档的转载，也不将参考架构当作产品实现。

## 先明确问题与语义

- 一张图先回答一个读者问题：系统边界、任务流程、状态迁移或数据比较。
- 名称、方向、条件和例外必须来自相邻正文或代码；禁止为排版添加不存在的依赖。
- 模型、宿主、执行资源、持久状态和离线改进分区表达；共享权限不是一次性的串行步骤。
- 运行成功、验收失败、修复、回退和发布不能混成同一种箭头。重要关系有文字标签，虚线与实线有图注。
- 不把抽象职责解释为独立进程，不把教学流程解释为真实测量。省略项在邻近图注中说明。

## 图型与唯一权威源

| 场景 | 表达方式 | 本仓库权威源 |
| --- | --- | --- |
| 模块总体架构 | 固定布局 SVG；复杂闭环拆运行与离线两图 | 对应模块 Markdown 中折叠的 Mermaid 源；脚本只维护位置、样式和明确图注 |
| 知识点与局部流程 | Mermaid 自动布局 | 对应 Markdown 代码块；网站不复制正文 |
| 知识与能力索引 | 清单生成的完整地图与精简预览 | `knowledge/modules.json`、`topics.json`、`units.json`、`capabilities.json` |
| 定量数据图 | 从数据和脚本生成 | 原始数据、统计口径和生成脚本，不能凭手绘制造数值 |

模块总体图由 `scripts/render_diagrams.py` 读取源图；`LAYOUTS` 只指定节点位置、连线路径和展示分区。修改节点或关系后必须同步布局并重新生成，脚本拒绝未布局节点与未知节点。Harness 两张展示图共同对应一份源图。

地图由 `scripts/render_maps.py` 生成。完整图保留全部主题或能力目标；预览只列每模块首项并明确标注，不能把删减预览冒充完整地图。

## 布局与可读性

- 主路径优先从左到右；反馈使用外侧通道。正交连线不得穿过节点正文。
- 节点同层同尺度，文字尽量一至两行；不得把关键条件截断。中文按显示宽度换行。
- 在约 900 CSS 像素正文宽度下，关键标签按至少约 14 像素检查；这是一项工程目标，不是 GitHub 强制标准。
- 使用克制的蓝、青、绿、橙、紫语义色，同时保留文字和线型，不能仅靠颜色判断。
- SVG 使用实体白色背景、深色文字、`viewBox`、`title` 和 `desc`。字体使用系统回退，不依赖远程字体、脚本或 `foreignObject`。
- 网站深色主题中图纸仍保持白底，不使用整图反色。局部图默认不缩小到原字号的 80% 以下；窄屏在图内滚动，不撑开整页。
- 超过 1100 原始像素且宽高比超过 3.5 的横向 Mermaid 流程在网站改为纵向布局，只改变全局阅读方向，不修改节点、箭头或权威源；图下明确提示。GitHub 仍使用原生源图布局。
- “适应宽度”允许用户主动缩小总览；原始比例、逐级缩放、全屏和下载提供细节阅读入口。全屏支持 Escape 关闭并恢复焦点。

## 路径与兼容

技术 SVG 保留在 `assets/` 第一层：`web/astro.config.mjs` 将其映射为站点资源，`web/src/lib/content.ts` 为直接子文件建立路由。新增子目录前必须调整扫描和测试。

Markdown 图片使用相对路径、有信息量的替代文字和原图链接；不能把 GitHub `blob` 浏览页当作网站图片地址。GitHub 使用固定 SVG 和原生 Mermaid；网站使用同源 SVG 和共享渲染主题。未实际访问的线上渠道不得声明通过。

## 修改与验收流程

1. 核对读者问题、事实来源、对象、边界及关键条件。
2. 选择总体图或局部图；复杂结构先拆分，不用无限加宽画布解决。
3. 修改权威源与固定布局，运行两类生成脚本的 `--write`。
4. 检查 [图示索引](图示索引.md)，同步正文、替代文字、原图入口和变化记录。
5. 运行 `--check` 和相关测试；若修改网站控件，执行类型检查、网站单测、构建和产物测试。
6. 使用真实浏览器或图形渲染器检查全部受影响图。XML 可解析、语法通过和测试通过不等于视觉通过。
7. 检查正文、全屏、中文字体、手机、浅深主题、失败降级和目标资源地址；在验收记录中保留具体结果、证据位置及未验证范围。

维护入口见 [图示索引](图示索引.md)。新增或修改图示时，内容维护者负责语义与导出同步，网站维护者负责展示和资源映射。
