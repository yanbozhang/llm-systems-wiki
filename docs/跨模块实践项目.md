# 跨模块实践项目

学习项目：设计一个可追溯的小型知识助手。目标是把七模块组合成完整方法，不要求立即训练大模型或部署应用。当前是实践设计，未在本仓库执行。

## 五个里程碑

| 阶段 | 任务 | 关联知识 | 可检查产物 |
|---|---|---|---|
| 来源与问题 | 选择少量可公开引用材料，设计单源、多源、无答案和冲突问题 | 来源接入、数据污染、RAG | 来源版本表、问题集与人工证据标注 |
| 模型与服务 | 定义token、输入模板、上下文预算、生成停止与时间线 | Transformer、SFT、KV缓存、Prefill/Decode | 输入样例、预算表与服务假设 |
| 检索与执行 | 设计召回、重排、上下文选择、任务状态与恢复 | 混合检索、Harness、记忆 | 候选列表、状态机与恢复检查点 |
| 评估 | 冻结数据、提示、解析和预算，区分组件与端到端指标 | Benchmark协议、RAG评测、裁判与统计 | 评测协议、逐题结果格式和失败分类 |
| 更新复盘 | 模拟一份来源更正，修订声明、页面与练习 | LLM Wiki、能力地图与持续更新 | 影响清单、变更记录与复习提示 |

## 完成标准

每个阶段能由另一个读者根据产物理解和复查。来源有版本，问题有独立判据，生成与评分分开，失败被保留，结果没有超出证据范围。

如果只做纸面推演，状态写“设计完成”；如果实际执行，保存环境、输入输出、脚本版本和资源预算，并区分运行成功与目标达成。没有实验数据时，不填写准确率提升或延迟收益。

## 分层选择

初学者先做来源、问题和一个手算检索例子；工程方向补充执行状态与服务指标；评测方向补充配对比较、污染检查及裁判校准。不要为了覆盖七模块而添加与目标无关的复杂组件。
