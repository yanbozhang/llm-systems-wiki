# 持续更新指南

v0.2把日常维护从“发现新资料”扩展为围绕能力目标完善知识单元。自动巡检负责来源候选与学习计划；正文编纂、事实核验和重要变化复核仍需维护者与助手完成。

模块及星期由[modules.json](../knowledge/modules.json)定义，主题来自[topics.json](../knowledge/topics.json)，计划不再将每模块四个主题写死。当前前六模块各四主题，Benchmark十一主题；完整覆盖周期分别为四周和十一周。重要更正可临时优先处理，并在复盘时记录被顺延项。

GitHub Actions每日上海时间08:00（UTC 00:00）巡检，平台可能延迟。计划输出包含主模块、具体主题、学习目标、预期产物及review_due；周日即使学习Benchmark，也保留复盘提示。

## 一次知识单元完善的流程

1. **选能力目标。** 从[能力地图](能力地图.md)选理解、推导、实践或评估目标，明确本轮交付物。
2. **补前置知识。** 核对正式先修与读者基础；缺口先补概念，不机械顺着最新论文推进。
3. **读课程与原始来源。** 课程帮助组织理解，原论文或官方文档支持具体技术结论；记录实际读取范围、年份和维护状态。
4. **形成独立示例。** 手算、状态推演或最小案例必须有假设和检查点；不能把课程标题改写成已掌握知识。
5. **设计或执行实践。** 先固定输入、预期与资源，再记录实际运行；未执行的保持designed，不写成功或性能收益。
6. **按协议评价。** 参考[Benchmark](../wiki/modules/Benchmark.md)，检查指标、数据、版本、预算、失败和不确定性。
7. **修订与发布。** 更新受影响的主题、声明、关系、能力目标、课程入口和练习；运行课程结构检查，并进行语义复核。
8. **复盘与复习。** 写清认识变化、来源依据及仍待核验项；个人学习记录绑定页面版本，不自动升级掌握状态。

本流程借鉴课程的前置、作业与反馈组织方法，具体取舍见[系统学习资源指南](系统学习资源指南.md)。它不是已经验证有效的学习效果承诺。

## 自动阶段和持久记录

工作流使用默认分支的维护脚本，按[feeds.json](../sources/manifest/feeds.json)顺序读取公开订阅。新增评测工具订阅与既有来源一起巡检；候选仍只有元数据，未经正文阅读不进入已确认知识。

结果保存到updates/candidates分支：runs记录逐轮结果，latest.json显示当前状态，state.json用于去重，study-plan.json记录本轮学习目标，baseline.txt绑定使用的代码基线。GitHub运行产物作为推送失败时的辅助恢复材料。

changed表示发现候选，unchanged表示所有源检查成功且无新候选；partial_failure与failed保留错误。成功采集并持久化后才推进检查点。候选分支其他文件可能来自旧知识基线，阅读正式知识使用main。

## 结构检查与语义复核

CI运行`python scripts/wiki_tool.py check --curriculum`，检查七模块、主题目录、能力引用、课程来源、必需章节和实践状态；本地链接与来源绑定仍按基础检查执行。

结构完整只是最低门槛。复核还要看示例是否成立、条件是否保留、引用是否支持结论、指标口径是否合理。章节达到字数门槛不代表内容正确；没有真实实验记录就不能标成复现支持。

## 周日和月度复盘

周日检查失效引用、未登记主题、先修环、来源更正、积压和偏科。月度按七模块四层能力盘点：哪些只有讲解、哪些有可检查示例、哪些有实践记录、哪些已有独立评测；据此更新[研究队列](研究队列.md)。

当前仍无无人值守LLM深度编纂、全文归档、全历史补采、向量问答服务或跨实例事务保障。订阅窗口有限，关键来源需定向回查；个人笔记始终单独保存。
